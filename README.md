# 孕期体重监测 v1.8.0

“公开分享准备版”是一款免费、纯静态、手机优先的孕期体重记录 PWA。它不需要账号和服务器数据库，不上传用户数据，全部设置与历史记录只保存在当前浏览器的 `localStorage` 中。

线上地址：<https://xiaobaicai236-source.github.io/pregnancy-weight-pwa/>

## v1.8.0 重点更新

- 修复未设置孕前体重时错误使用 `0 kg` 计算的问题。
- 将孕周统一为 1–40 周、天数统一为 0–6 天，并安全跳过旧版越界记录。
- 新增身高、孕前 BMI 分类和单胎/双胎设置。
- 默认计算标准调整为国家卫生健康委员会 WS/T 801—2022，并采用中国成人 BMI 切点。
- 单胎自然妊娠根据四种孕前 BMI 类别选择中国参考参数；双胎不套用普通曲线，并发症情况下仅淡化保留通用趋势参考。
- 支持录入、编辑、删除、暂停和清空医生提供的个体化目标点；目标曲线只在录入点之间插值，不外推或编造参数。
- “近期增重速度”和“近4周增速”统一使用最近四周窗口；不足两条或间隔不足 14 天时不作判断。
- 图表删除重复的外部横坐标，增加“参考范围”图例，并支持点击实际点和推荐点。
- 图表增加按天吸附的触摸/鼠标十字定位，可查询任意孕周的推荐中位数，并保留记录点详情交互。
- 强化 JSON 导入校验、重复记录处理和恶意内容防护。
- 全部静态资源与 Service Worker 缓存统一为 `v1.8.0`。
- 增加公开分享所需的来源、隐私和医学免责声明。
- 支持 iPhone 手动添加到主屏幕，以及 Android 等浏览器的原生 PWA 安装流程。
- 新增独立的 Android maskable 图标。

## 主要功能

- 记录孕周、天数和当前体重。
- 当前体重输入保留用户正在输入的原始小数字符串，失焦、Enter 或键盘“完成”后才确认保存，不会在停顿时自动补 `.0`。
- 同一孕周天数再次输入时覆盖原记录。
- 编辑、删除或清空历史记录。
- 显示累计增重、相对推荐位置和近四周趋势。
- Canvas 绘制实际体重、推荐中位线和参考范围。
- 医生目标点可包含上下限和可选中位数；缺少中位数时仅显示“范围中点”，不会表述为医生推荐中位数。
- 按住左右滑动或移动鼠标，临时查询 1–40 周的推荐上限、推荐中位数和推荐下限；手机端会锁定已识别的横向查询手势，同时保留从图表开始纵向滚动页面的能力；查询状态不会写入体重记录。
- 根据孕前身高、体重和胎数显示适用参考。
- 导出和导入 JSON 备份。
- 跟随系统深色/浅色模式。
- 安装到手机主屏幕并离线运行。
- 无登录、云同步、广告或分析追踪。

## 医学参考与计算口径

BMI 按 `孕前体重 kg ÷ 身高 m²` 计算：

- 低体重：BMI < 18.5
- 正常体重：18.5 ≤ BMI < 24.0
- 超重：24.0 ≤ BMI < 28.0
- 肥胖：BMI ≥ 28.0

### 单胎参考

默认计算采用中华人民共和国国家卫生健康委员会 WS/T 801—2022。以下单位为 kg 和 kg/周。

| 孕前 BMI | 全程总增重 | 孕早期增重 | 中、晚期每周推荐值及范围 |
|---|---:|---:|---:|
| 低体重 | 11–16 | 0–2 | 0.46（0.37–0.56） |
| 正常体重 | 8–14 | 0–2 | 0.37（0.26–0.48） |
| 超重 | 7–11 | 0–2 | 0.30（0.22–0.37） |
| 肥胖 | 5–9 | 0–2 | 0.22（0.15–0.30） |

官方对孕早期只提供 0–2 kg 的阶段范围。页面中的孕早期逐周线是基于该阶段范围生成的趋势参考，并非官方逐周标准值；中、晚期曲线及增重速度判断使用表中的中国推荐值和范围。

### 双胎参考

WS/T 801—2022 仅适用于单胎自然妊娠。选择双胎时不绘制普通参考曲线、不显示普通“偏快/偏慢”结论，并提示咨询产检医生；基础记录功能不受影响。

### 数据来源

- 主要依据：[中华人民共和国国家卫生健康委员会 WS/T 801—2022《妊娠期妇女体重增长推荐值标准》](https://www.nhc.gov.cn/wjw/c100311/202208/deb61e5c2299451ea1b957b0672272b3.shtml)。发布机构：中华人民共和国国家卫生健康委员会；发布日期：2022年7月28日；实施日期：2022年10月1日；适用于我国妇女单胎自然妊娠。
- 补充参考：[CDC — Weight Gain During Pregnancy](https://www.cdc.gov/maternal-infant-health/pregnancy-weight/index.html)；[National Academies / IOM 2009](https://nap.nationalacademies.org/catalog/12584/weight-gain-during-pregnancy-reexamining-the-guidelines)。补充来源不参与中国用户的默认计算。

所有参数集中存放在 `data.js`，并使用 kg、cm 和 kg/周作为页面单位。

## 重要医学说明

本工具只用于日常体重记录和趋势参考，不替代产检、医生建议或医学诊断。当前标准适用于我国成年女性单胎自然妊娠。身高低于 140 cm、孕前体重超过 125 kg或双胎时不生成通用参考曲线。妊娠期糖尿病、其他妊娠并发症或医生已经制定个体化目标时，不使用通用范围作“偏快/偏慢”结论；符合单胎通用标准时，通用曲线仅作为淡化背景对照。医生目标数据完全由用户按医生明确建议录入，本工具只进行校验、记录和相邻点线性绘图，不推断诊断、治疗目标或未提供孕周的数据。体重记录始终保留。短时间体重变化可能受测量时间、饮食和水分影响，因此记录间隔不足 14 天时也不会给出快慢判断。

## 数据与隐私

- 主存储键继续使用 `pregnancy-weight-pwa-v1`，升级不会主动清空旧数据。
- 新增 `heightCm`、`plurality`、`pluralityConfirmed`、`hasPregnancyComplication`、`hasDoctorTarget`、`doctorPlanEnabled`、`doctorPlanVersion` 和 `doctorTargets` 字段；旧数据缺失新字段时使用安全默认值，不删除记录。
- 旧数据没有身高时会保留体重记录，并提示补充身高。
- 旧数据没有胎数时暂按单胎读取，但会提示用户确认。
- 页面不收集姓名、电话号码、身份证、预产期或其他不必要信息。
- 数据不会上传到网站运营者或第三方。
- 清除浏览器数据、删除网站数据或换手机可能导致记录丢失。
- 网站运营者无法找回本地记录，建议定期导出 JSON 备份。

## 备份兼容

v1.8.0 当前导出备份 schema 版本 3，包含孕前体重、身高、胎数、当前孕周、BMI 快照、个体化选项、医生目标显示状态、医生目标点和历史体重记录。BMI 仍会在导入后根据身高和体重重新计算。schema 版本 1 和 2 继续允许导入。

旧版 schema 版本 1 继续允许导入：

- 缺失身高时保持未设置状态。
- 缺失胎数时暂按单胎处理并提示确认。
- 缺失记录 ID 时根据孕周和天数安全生成。
- 无效或重复记录会被跳过并计数。
- 旧备份没有医生目标字段时使用空列表和安全默认值，现有本机医生目标及体重记录不会因合并导入被删除。
- 根级资料无效时拒绝整个文件，不覆盖现有数据。

导入完成后会显示合并/更新、跳过和无效记录数量。

## PWA 安装

### iPhone Safari

1. 用 Safari 打开网站。
2. 点击“分享”。
3. 选择“添加到主屏幕”。
4. 从主屏幕图标启动后，页面以独立模式运行。

iPhone Safari 不提供网页主动弹出安装窗口的能力，因此页面只显示正确的手动操作说明。

### Android Chrome、Edge、三星浏览器等

当浏览器确认当前网站满足 PWA 安装条件并触发 `beforeinstallprompt` 时，页面底部才显示“安装应用”按钮。点击后使用浏览器的原生安装流程。安装成功或已经以 standalone 模式运行时，安装提示会隐藏。

如果浏览器不支持原生安装，网站全部记录和计算功能仍可正常使用，不会显示无效按钮。页面底部会根据 iPhone/iPad、Android、应用内置浏览器、桌面浏览器和 standalone 状态显示对应说明，不会向所有平台展示同一套操作。

### 微信、QQ等内置浏览器

内置浏览器通常不支持标准 PWA 安装。页面会提示通过右上角菜单在 Safari 或系统浏览器中打开。关闭安装提示后 14 天内不会重复打扰。

## GitHub Pages 部署

1. 将仓库文件放在 GitHub 仓库根目录。
2. 打开仓库 **Settings → Pages**。
3. Build and deployment 选择 **Deploy from a branch**。
4. 选择 `main` 分支和 `/ (root)` 目录。
5. 保存并等待 Pages 构建完成。

`manifest.json` 的 `id`、`start_url`、`scope` 以及所有缓存 URL 都使用相对路径，兼容 GitHub Pages 子目录部署。Service Worker 需要 HTTPS；GitHub Pages 默认提供 HTTPS。

## 从旧版本升级

完整覆盖仓库静态文件，并保留 `assets/` 目录。不要更改 LocalStorage 主键。

发布后：

1. 在线重新打开并刷新一次。
2. 等待 Service Worker 获取 v1.8.0 静态资源。
3. 如果仍显示旧界面，关闭标签页后重新打开。
4. 极端情况下可删除该网站的缓存后重开；删除网站数据会同时删除本机体重记录，因此应先导出备份。

新版 Service Worker 会清理旧 Cache Storage，但不会操作 LocalStorage。

## 本地预览与测试

直接双击 `index.html` 无法完整测试 Service Worker。请运行静态服务器：

```bash
python -m http.server 8080
```

然后访问 `http://127.0.0.1:8080/`。

核心测试不需要第三方依赖：

```bash
node tests/chart.test.js
node tests/core.test.js
node tests/pwa.test.js
```
